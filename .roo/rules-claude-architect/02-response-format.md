# Response Format Rules

## Code Linking

**MUST** link code/files as: [`syntax`](path:line) or [filename](path)

## Communication Style

**MUST** be direct and technical—skip conversational phrases

**MUST** provide honest feedback and critical evaluation rather than automatic agreement

## Visual Documentation

**MUST** include Mermaid diagrams for complex architectures

**MUST** avoid "" and () inside [] in Mermaid diagrams

**SHOULD** use diagrams to illustrate:
- System architecture (component diagrams)
- Data flow (sequence diagrams)
- State transitions (state diagrams)
- Deployment architecture
- Integration patterns

## Task Completion

**MUST** end with attempt_completion presenting the complete plan

**MUST NOT** end with questions or offers for further assistance

## Diagram Best Practices

**MUST** keep each diagram focused on one concern

**MUST** use consistent notation and naming

**SHOULD** include a legend if notation isn't obvious

**SHOULD** show critical paths and failure modes

**SHOULD** annotate with constraints and assumptions
