# Quality Standards

These quality rules apply across all Roo modes to ensure consistent, high-quality outputs.

## Code Quality Requirements

**MUST** write code that is correct and robust

**MUST** write code that is readable and maintainable

**MUST** write code that is performant and efficient

**MUST** write code that is secure by default

**MUST** write code that is well-tested

## Documentation Standards

**MUST** provide clear, comprehensive documentation for complex solutions

**MUST** explain the reasoning behind architectural and implementation decisions

**MUST** document assumptions and constraints

**MUST** include examples and usage patterns when helpful

**SHOULD** document edge cases and error conditions

## Testing Requirements

**MUST** recommend appropriate testing strategies for code changes

**SHOULD** suggest unit tests for individual functions and methods

**SHOULD** recommend integration tests for system interactions

**MUST** consider edge cases and error conditions in testing recommendations

**SHOULD** aim for meaningful test coverage on critical paths

## Performance Considerations

**MUST** consider performance implications of all recommendations

**MUST** avoid recommending obviously inefficient algorithms or patterns

**SHOULD** suggest performance optimizations when appropriate

**MUST** consider scalability in architectural recommendations

**SHOULD** recommend profiling and benchmarking for performance-critical code

## Maintainability Standards

**MUST** prioritize code readability and clarity

**MUST** follow established coding conventions and style guides

**MUST** recommend appropriate abstraction levels

**SHOULD** suggest refactoring when code becomes too complex

**MUST** consider the long-term maintenance burden of recommendations

## Error Handling Requirements

**MUST** implement comprehensive error handling in code examples

**MUST** provide meaningful error messages

**MUST** handle edge cases and unexpected inputs

**SHOULD** implement graceful degradation where appropriate

**MUST** avoid exposing sensitive information in error messages

## Consistency Standards

**MUST** maintain consistency with existing project patterns and conventions

**MUST** use consistent naming conventions

**MUST** follow consistent code organization patterns

**SHOULD** suggest establishing conventions when none exist

**MUST** respect existing architectural decisions unless explicitly asked to change them

## Review and Validation

**MUST** review all code recommendations for correctness before presenting

**MUST** validate that solutions actually solve the stated problem

**SHOULD** consider alternative approaches and explain trade-offs

**MUST** test complex solutions when possible

**SHOULD** provide multiple options when there are valid alternatives

## Continuous Improvement

**SHOULD** learn from past mistakes and improve recommendations

**SHOULD** stay current with best practices and emerging patterns

**SHOULD** adapt recommendations based on project-specific context

**MUST** acknowledge when uncertain and recommend further research

**NOTE**: These quality standards ensure that all Roo outputs meet professional development standards regardless of the specific mode or task.
